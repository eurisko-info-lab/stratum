```text
semantic-fs: establish semantic filesystem authority, govern materialization, and keep patch application constructive
```

## Feature

Structured content is the repository authority for declared languages, with
governed materialization policies and constructive patch application at the
repository boundary.

$$
F_{12} = F_{11} + \text{semantic filesystem authority and governed materialization}
$$

## What changed

1. The semantic filesystem is authoritative over surface encodings.
2. Structured-content identity is explicit and stable at tree-entry level.
3. Materialization is governed by explicit, auditable policy.
4. Repository patches are constructive, not only checkable:

$$
\operatorname{ApplyTreePatch}(T_{n-1},\delta_n)=T_n
$$

5. Verification enforces materializer/reader/blob/grammar invariants.

## Interpretation

The governing acceptance law remains semantic fixpoint, not byte identity:

$$
\operatorname{Parse}(\operatorname{Print}(\operatorname{Parse}(x)))=\operatorname{Parse}(x)
$$

So F12 remains the semantic-filesystem layer rather than a container for later
schema or agent abstractions.
