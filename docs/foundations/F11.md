## Three separate schemas

| Schema | Defines | Where |
| --- | --- | --- |
| `LanguageSchema` | meaning | [features/tooling/tooling.meta](../../features/tooling/tooling.meta) |
| `ToolchainSchema` | tool roles | [features/tooling/tooling.meta](../../features/tooling/tooling.meta) |
| `StudioProfile` | interaction | [features/studio/studio.meta](../../features/studio/studio.meta) |

A `StudioProfile` must not alter language semantics. `RelayoutProfile` changes
the layout of a profile and leaves the language digest untouched.

## One generic runtime

The runtime offers only these primitives:

```text
tree list table text form graph inspector diff conflict preview queue palette
```

`ValidateViews` rejects a profile that asks for anything else, so no profile can
smuggle in a bespoke widget. There is no Scala UI class per application.

## Two visibly different studios

The platform demonstrates this with two profiles that have no domain between
them, because a platform that demonstrated it with a real domain would be a
platform that knows that domain. Applications carry their own profiles, on
their own branches.

| | `alpha` | `beta` |
| --- | --- | --- |
| layout | `single-pane` | `split-pane` |
| navigation | flat: root → item | nested: group → item |
| panels | outline, detail | index, body, log |
| commands | open item | create item, review item |
| workflow | open → closed | draft → review → done |
| field editors | plain text | rich text, numeric |
| previews | plain text | archive |

`ProfilesDifferIn` reports `(differences #f #f #f #f #f #f #f)`: every one of the
seven comparisons differs. `StudiosCollapse` is `#f`, and `SharesRuntime` is
`#t`, so they differ in interface while sharing the runtime.

## The complete round trip

`RoundTripStages` names seventeen stages and `RunRoundTrip` executes each one
against the live foundation:

```text
finalized-publication      fetch-closure            create-local-branch
derive-tooling             change-language          change-code
change-data                record-patches           commute-independent-patches
explicit-conflicts         run-acceptance           package-proposal
peers-fetch-closure        settle-transition        advance-chain
reconstruct-on-fresh-node  reopen-studios
```

Each stage is a real derivation: changing a language is a keyed grammar edit,
changing code is a semantic path edit on a lambda term, changing data is a Meta
declaration insert, acceptance runs the proof-requiring constitution, and the
final stage reopens a generated studio over the reconstructed state.
