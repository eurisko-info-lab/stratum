# F7 — signed publication ledger

```text
ledger: add signed publication blockchain in F7
```

## Feature

A signed append-only chain for publication and foundation history. There is no
network and no agreement protocol yet: the chain has one designated authority.

$$
F_7 = F_6 + \text{signed publication ledger}
$$

## Meta change

[features/ledger/ledger.meta](../../features/ledger/ledger.meta) declares
`Transaction`, `Block`, `ChainState`, `ChainPosition`, `Publication` and the
replay and validity judgments.

A block contains its predecessor block, ordered transactions, publication roots,
the resulting state transition, an author identity, a signature and resource
evidence.

## What the chain anchors

A publication may anchor a repository branch frontier, an application root, a
foundation root, a language package, a data package or an archive root. The chain
does not contain local development activity.

## Chain and repository relationship

1. choose a finalized chain publication
2. create a local repository branch from its root
3. develop offline
4. produce accepted patches
5. package a proposed publication
6. append it under the single-authority constitution

`BranchFromCheckpoint` performs step 2 by recording a patch that installs the
published root as the branch base.

## Validity

| Rejection | Reason |
| --- | --- |
| block does not follow the previous block | `broken-predecessor-link` |
| block author is not the designated authority | `wrong-authority` |
| block signature does not verify | `bad-block-signature` |
| transaction author is not entitled | `unentitled-author` |
| transaction was altered after signing | `bad-transaction-signature` |
| repository head was never accepted | `unaccepted-repository-head` |

## Reconstruction

`ReconstructPublished` fetches the published root from the closure, so published
state is reconstructed from chain plus closure, never from a snapshot carried in
a block.
