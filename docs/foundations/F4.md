# F4 — schema-derived language toolchains

```text
tooling: derive language toolchains from schemas in F4
```

## Feature

Language tooling is derived from declarations instead of hand-written
application code.

$$
F_4 = F_3 + \text{schema-derived language toolchains}
$$

## Meta change

[features/tooling/tooling.meta](../../features/tooling/tooling.meta) declares
`LanguageSchema`, `ToolchainSchema`, `Tool`, `Toolchain` and `Finding`. A
language says which judgment plays which role:

```text
parse print typecheck evaluate normalize compile executeTarget
format index rename diagnostics validateChange
```

## Derived tools

`DeriveToolchain` produces one canonical `Tool` artifact per declared role. A
tool identity is

$$
\mathsf{id}(t) = H(\mathsf{encode}(\texttt{(tool-identity language role program grammar)}))
$$

so it depends only on the schema selection and the selected program. Changing the
grammar changes the identity of every tool that depends on it.

`RunRole` is a generic runner over declared roles: adding a language is a Meta
change, never a host change. No language-specific compiler, formatter, index or
editor exists in Scala, which
[test-scala/NativeBoundarySuite.scala](../../test-scala/NativeBoundarySuite.scala)
enforces.

## Compiler model

$$
\mathsf{Compile}_{S,T} : S \to T
$$

The target is a tiny stack machine declared as an ordinary language artifact
(`StackSchema`, sorts `Code` and `Instruction`, constructors `ACCESS`, `FREE`,
`GRAB`, `PUSH`) with no concrete syntax of its own.

```text
compile(var i)   = [ACCESS i]
compile(free n)  = [FREE n]
compile(lam b)   = [GRAB (compile b)]
compile(app f a) = PUSH (compile a) :: compile f
```

Execution is a Krivine-style machine plus readback, so

$$
\mathsf{TranslationPreservesMeaning}
$$

holds on the regression corpus: compiled execution and direct normalization
produce the same canonical term.
